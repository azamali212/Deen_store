Seller Domain — progress tracker
=================================

WHY THIS DOMAIN EXISTS
-----------------------
CreateUserRequest / RegisterSellerRequest were already collecting
store_name / business_name / business_type at registration time, but
there was NO table anywhere to persist them — AuthService::createUser()
only ever read name/email/password/phone into CreateUserData. Every
seller who registered had their store info silently discarded.

Deliberately NOT added as columns on `users` or folded into the User
domain — a seller's store is a different concern from a person's
identity (same reasoning as why Suspend/Activate stayed separate from
Auth's Lock/Unlock). Amazon/eBay's user/identity service does not own
storefront data either — it's a separate bounded context that
references the user by ID.

WIRED IN
--------
- app/Providers/AppServiceProvider.php — SellerRepositoryInterface bound.
- app/Http/Requests/Auth/CreateUserRequest.php — store_name rule gained
  `unique:seller_profiles,store_name`.
- app/Http/Controllers/Auth/BaseAuthController::register() — now wraps
  user creation + (conditional) seller-profile creation in ONE
  DB::transaction(). If role === SystemRole::SELLER, CreateSellerProfileAction
  runs right after CreateUserAction, inside the same transaction, so a
  seller can never end up with a User row and no Store row (or vice versa).
  Response now includes a `seller_profile` block when applicable.
