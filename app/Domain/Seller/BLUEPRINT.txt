SELLER ONBOARDING MODULE — PROTOTYPE / BLUEPRINT (not built yet)
================================================================================
Status: PLANNING ONLY. Nothing in this file exists as code yet — this is the
agreed structure before we start writing files. Confirmed decisions so far:
  - Documents required: cnic_front, cnic_back, business_license,
    tax_certificate, bank_statement (5 types)
  - Rejection flow: user edits the SAME application and resubmits (status
    goes rejected -> pending again), not a brand-new application row.
  - Bank account number must NOT be stored plaintext (encrypted cast, or
    last-4-digits only) — enterprise/security requirement, decided upfront.

1. WORKFLOW DIAGRAM (full lifecycle, both actors)
--------------------------------------------------------------------------------

  CUSTOMER                         SYSTEM                          ADMIN
  ────────                         ──────                          ─────

  [Logged-in customer,
   already has a profile]
        │
        │ 1) Click "Start Business"

        │

        │    business_license, tax_certificate,

        │
        ▼

        │

        │                                                              │

        │                                                     GET /admin/seller-applications

        │                                        ├─► status = approved                       ├─► status = rejected

        │                                        ├─► user gets 'seller' role (spatie)         │
        │                                        │                                            │
        │                         event: SellerApplicationApproved              event: SellerApplicationRejected
        │                                        │                                            │
        │                     ┌──────────────────┴──────────────┐                             │

2. DATABASE TABLES
--------------------------------------------------------------------------------

seller_applications
  id, user_id (FK, indexed), store_name, business_name, business_type,
  status (pending/under_review/approved/rejected), rejection_reason (nullable),
  reviewed_by (FK users, nullable), reviewed_at (nullable), timestamps
  UNIQUE(user_id)        -- one active application per user at a time
  UNIQUE(store_name)     -- no two sellers share a public store name

seller_application_documents
  id, seller_application_id (FK), document_type (enum string), file_path,
  uploaded_at, timestamps
  UNIQUE(seller_application_id, document_type)  -- re-upload replaces, never duplicates

seller_profiles           -- created ONLY on approval, this is the LIVE business
  id, user_id (FK, unique), seller_application_id (FK, reference back to how
  they got approved), store_name, business_name, business_type, logo_path,
  description, business_address, bank_account_title, bank_name,
  bank_account_last4 (string(4) — NEVER the full number), status
  (active/suspended), timestamps
